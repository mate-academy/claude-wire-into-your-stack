# NOTES

**MCP server.** Connected `git` — `@cyanheads/git-mcp-server`, a Node-based MCP server exposing ~28 git operations (status, diff, commit, branch, log, push/pull, stash, worktree, etc.) as structured tool calls. Useful here because it gives git operations a typed tool interface instead of parsing raw CLI output through Bash, and because the obvious first choice — the official Python `mcp-server-git` via `uvx` — can't run on this machine at all (this is ARM64 Windows, and its `cryptography` dependency has no prebuilt wheel for that platform, so it fails compiling from source). The permission rule allowed the `git` server via `enabledMcpjsonServers` in the local, gitignored settings file only — nothing in the committed `.mcp.json` hardcodes a machine path, so the config stays portable for anyone who clones the repo.

**Skill.** `add-crud-resource` captures this project's repeated shape for adding a new REST resource: store helpers in `db/store.js`, a router in `routes/<resource>.js` mirroring `routes/users.js`'s GET/POST/PUT + 400/404 conventions, a test file mirroring `tests/users.test.js`, and a new section in `docs/api.md`. The description is worded to name the trigger phrases directly ("add a `/products` resource", "add CRUD endpoints for orders", "wire up a new collection") and explicitly excludes adjacent cases ("modifying an existing resource's routes, unrelated Express work") so it doesn't fire on every Express-flavored request.

**Command.** `/check-conventions` reviews a route file (or the working diff) against the four rules in `CLAUDE.md` — one route file per resource, no state outside `db/store.js`, 400/404 validation, and the `{ "error": "message" }` shape. It's worth a shortcut because it's the kind of check I'd otherwise re-explain from scratch each time; as a saved command it's one word instead of re-deriving the checklist.

**Hook.** `PostToolUse` on `Edit|Write` runs `node .claude/hooks/lint-fix.js`, which auto-fixes the specific file just touched with the project's own local ESLint. It's a *reactive* hook, not a preventive one — it fixes lint issues after they land rather than blocking the edit, which fits auto-formatting (nothing to gate before the file exists) but wouldn't fit something that needs to stop an action outright (that's what `PreToolUse` is for).

**Headless run.** Ran `claude -p` to scaffold a `/products` CRUD resource end-to-end (store functions, router, tests, docs). Locked it down to: unrestricted `Read`/`Glob`/`Grep`/`Skill` (read-only or skill-invocation, no risk), `Edit` scoped to the three specific files it needed to modify (`server.js`, `docs/api.md`, and initially `db/store.js`), and `Bash` scoped to only `npm test` and `npm run lint` — no general shell access. `Write` ended up ungated after path-scoped grants (`Write(routes/**)`, then exact `Write(routes/products.js)`) both failed to match, since `Write` always receives an absolute path while the scoping appears to match on relative paths; the containment there came from a narrowly-worded prompt instead. Twice, the tightly-scoped run hit the edge of its permissions and stopped to ask rather than improvising past them — which is the actual point of the exercise.
