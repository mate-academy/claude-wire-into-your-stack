# NOTES

## Сервер (MCP)

Підключив **context7** (`@upstash/context7-mcp`) на рівні проєкту через `.mcp.json`.
Він підтягує актуальну документацію бібліотек (наприклад Express) прямо в розмову —
корисно саме для цього репо, бо це Express API і Claude регулярно потребує звірити
поведінку `express.Router()`, middleware чи валідації параметрів з офіційними
доками, а не покладатися на пам'ять. Сервер не потребує ключа (безкоштовний рівень
без автентифікації, ключ лише піднімає rate limit). Правило дозволу в
`.claude/settings.json` дозволяє тільки два read-only інструменти сервера —
`resolve-library-id` і `query-docs` — а не весь сервер блоком. Перевірив наживо:
попросив Claude знайти в доках Express, як `router.param()` валідує параметри
маршруту, і отримав коректну відповідь із двома реальними викликами інструментів.

## Skill

Скіл `add-express-route` (`.claude/skills/add-express-route/SKILL.md`) фіксує
повторюваний спосіб додавання ресурсу в цей проєкт: спочатку функції в
`db/store.js`, потім один файл роуту в `routes/`, валідація прямо в роуті
(400 на поганий ввід, 404 на відсутній запис), формат помилки рівно
`{ "error": "message" }`, підключення в `server.js`, тести за зразком
`tests/users.test.js`, оновлення `docs/api.md`. Опис у фронтматері явно
перелічує тригер-фрази ("add a route for X", "create an endpoint for Y",
"add a new resource") і згадує конкретні файли/патерни, тому скіл спрацьовує
на прохання додати ресурс — перевірив без прямої назви скіла ("Add a new
resource to this API for tracking 'notes'…") і Claude сам обрав саме цей скіл.

## Command

Команда `/check-conventions` (`.claude/commands/check-conventions.md`) прогонює
чекліст конвенцій проєкту (структура роутів, доступ через `db/store.js`, коди
400/404, формат помилки, доки, тести, lint/test) проти поточного diff або
вказаного шляху — без внесення правок. Вартий шорткату, бо це саме та перевірка,
яку хочеться робити перед кожним комітом з новим роутом, а руками перечитувати
CLAUDE.md щоразу незручно. Прогнав на `routes/users.js` — команда коректно
знайшла реальну прогалину (немає тестів на 400-кейси) і повідомила, що
залежності на той момент не були встановлені.

## Hook

`PostToolUse` на `Edit|Write` (`.claude/settings.json` → `.claude/hooks/lint-fix.js`)
запускає `eslint --fix` на щойно зміненому `.js`-файлі. Обрав реагувати
(PostToolUse), а не блокувати (PreToolUse), бо це стандарт стилю, який варто
автоматично підтягувати, а не зупиняти роботу заради нього. Матчер — тільки
`Edit|Write`, бо саме ці інструменти змінюють файли. Перевірив: навмисно залишив
у файлі зайве подвійне заперечення (`!!req.query.ok`, помилка `no-extra-boolean-cast`),
попросив Claude зробити незалежну правку в тому ж файлі — хук автоматично
прибрав `!!` без жодної додаткової команди з мого боку.

## Headless-запуск

Запустив `claude -p` для одного точкового завдання: додати тести для
`GET /health` (єдиного роуту без покриття тестами), за стилем `tests/users.test.js`.
Дозволив лише `Read`, `Write` і `Bash(npm test)` — без `Edit` (файл новий,
редагувати нема чого), без Bash з інших команд і без мережевих/MCP-інструментів,
бо завдання суто локальне: прочитати існуючий тест як зразок, написати новий
файл, прогнати `npm test` для самоперевірки. Результат — `tests/health.test.js`,
усі 6 тестів проходять.
