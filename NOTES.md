# Notes

**Server:** Connected a `filesystem` MCP server (`@modelcontextprotocol/server-filesystem`), rooted at `./docs`, at project scope (`.mcp.json`, committed). It's useful here because it gives Claude direct, read-only access to the project's docs folder without going through the general-purpose file tools, and it's a config other contributors get for free once they approve it. The permission rule in `.claude/settings.json` allows only the read-only tools — `read_text_file`, `read_multiple_files`, `list_directory`, `directory_tree`, `search_files`, `get_file_info`, `list_allowed_directories` — so it can browse and read `docs/` but never write to it.

**Skill:** `add-crud-resource` captures the repeated shape of adding a new resource to this API: store helpers in `db/store.js`, a route file mirroring `users.js` (list/get/create/update with the 400/404 rules), mounting it in `server.js`, and a test file mirroring `users.test.js`. The description is worded around the concrete verbs and nouns that show up in a real request for this ("add, create, or wire up a new resource/endpoint/route for a noun") with examples, plus an explicit negative ("do not use for editing an existing route's behavior... or non-resource endpoints like health checks") so it doesn't fire on unrelated edits. It triggered correctly on "Add a products endpoint with name and price fields" without naming it.

**Command:** `/check-conventions` reviews a diff, path, or commit against this project's four conventions (JSON `{error}` shape, 400/404 split, all data access through `db/store.js`, one route file per resource). It's worth a shortcut because this project's CLAUDE.md conventions aren't enforced by any linter — they're a judgment call only a prompt can check — and this is exactly the kind of review that's easy to forget to run manually after scaffolding a new route by hand.

**Hook:** A `PostToolUse` hook on the `Edit|Write` matcher — it *reacts* to a completed edit rather than *preventing* one, since auto-fixing lint issues doesn't need to gate the write. It pulls `tool_input.file_path` via `jq` and runs `npx eslint --fix` on it when the path ends in `.js`, so the project's lint standard is applied automatically on every edit instead of only when someone remembers to run `npm run lint`.

**Headless:** Ran the `orders` resource scaffold (same shape as `products`, via `claude -p` and the `add-crud-resource` skill) with no one watching. Locked down to `--allowedTools "Read" "Write" "Edit" "Skill" "Bash(npm test)" "Bash(npm run lint)"` — enough to scaffold files, invoke the skill, and verify the result, but no general shell access and no `git`, so it couldn't commit or touch anything outside the four files the task needed. I verified the result and committed it myself afterward.
