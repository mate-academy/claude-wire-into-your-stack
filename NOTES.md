# NOTES

**Server:** Connected the official `@modelcontextprotocol/server-filesystem`, scoped to `${CLAUDE_PROJECT_DIR}/docs` (see `.mcp.json`). It's useful here because the repo keeps its canonical API reference in `docs/api.md`, and this gives any MCP client a read-only, project-scoped way to browse that reference without touching the rest of the codebase. Chose it over a fetch server for pulling in *external* references because this machine has no Python/`uv` installed, while `npx` (already required by the project) works out of the box. The permission rule in `.claude/settings.json` allows only `mcp__filesystem__read_text_file`, `list_directory`, `search_files`, and `get_file_info` — the read-only tools actually needed — leaving out `write_file`, `edit_file`, `create_directory`, and `move_file` that the server also exposes.

**Skill:** `scaffold-api-resource` (`.claude/skills/scaffold-api-resource/SKILL.md`) captures the repeated four-file shape every resource in this API follows: CRUD helpers in `db/store.js`, a router in `routes/<resource>.js` with the project's exact validation/404/error-shape conventions, mounting in `server.js`, and a test file mirroring `tests/users.test.js`. The description names concrete trigger phrases ("add a posts resource", "create a comments endpoint") and explicitly excludes editing/fixing existing routes, so it fires on "stand up a new resource" requests and nothing else.

**Command:** `/check-conventions` (`.claude/commands/check-conventions.md`) reviews a diff or a given path against the five conventions in `CLAUDE.md` — validation returns 400, missing records return 404, the `{ error }` shape, data access only through `db/store.js`, one route file per resource — and reports violations without fixing them. It's worth a shortcut because it's the kind of pre-commit sanity check that's easy to skip under time pressure but cheap to run on demand.

**Hook:** A `PreToolUse` hook on the `Bash` matcher, filtered with `"if": "Bash(git commit*)"`, so it only runs when the command being invoked is a `git commit`. It *prevents* rather than reacts: it runs `npm run lint` first and exits `2` (blocking, with a stderr message) if lint fails, letting the commit through only when lint is clean. Chose PreToolUse/prevent over a PostToolUse auto-fix because a broken lint state shouldn't become a commit in the first place.

**Headless run:** Ran `/check-conventions routes/users.js` via `claude -p "/check-conventions routes/users.js" --allowedTools "Read,Grep,Glob"`. Locked it down to those three read-only tools — no `Bash`, `Edit`, or `Write` — since the task only needed to read the target file and cross-reference `db/store.js`, `server.js`, and `CLAUDE.md`; passing a file path directly meant it never needed the command's `git diff` fallback, so no git access was granted either. The run found three real validation gaps (a malformed `:id` falling through to 404 instead of 400 on both `GET` and `PUT`, and `PUT` accepting an empty `name`/`email` that `POST` would reject), confirming the review is substantively useful and not just a formality. One incidental finding: on a fresh checkout, the first headless run on this workspace prints a one-time "workspace not trusted" warning before proceeding — worth knowing about, not a blocker.
